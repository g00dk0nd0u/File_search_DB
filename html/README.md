# Edge用ローカルHTML版 Folder Search

既存Python版と並行して使う、独立したファイル名・フォルダ名検索アプリです。
仕様の正本は [Issue #2](https://github.com/g00dk0nd0u/File_search_DB/issues/2) です。

**Windows Edgeの `file://` 実機受入は未検証です。** この開発環境ではWindows Edgeを利用できず、代替のLinux Chromiumも管理ポリシーで `file://` とフォルダ読み取りAPIが禁止されていました。動作保証・Done扱いはしていません。サーバー方式への変更は行っていません。

## 起動

1. `html/` を内容ごと展開し、同じ配置を保ちます。
2. `index.html` を右クリック →「プログラムから開く」→ Microsoft Edge。既定ブラウザがEdgeならダブルクリックで開きます。
3. Settings → Add Directory で検索対象を選び、読み取りを許可します。初回の走査後、Back to Search へ戻ります。
4. Search Targetを選び、キーワードを入力します。入力後250msで検索、またはSearch / Enterで実行します。日本語IMEの変換中は検索を待ちます。
5. フォルダ行をクリックして展開し、直下のファイルを選ぶと右側にプレビューが表示されます。子フォルダを選ぶと浅いフォルダプレビューへ移動します。

実行時のPython、Node.js、ビルド、Webサーバー、localhost、ブラウザ拡張、CDN、外部API、ネットワーク通信は不要です。通常のclassic scriptと相対CSSのみを読み込みます。module、fetch、Workerは使用しません。CSPでも通信と外部リソースを禁止しています。

## 操作と検索仕様

- 複数ルートを登録し、一度に1つ選択して検索します。同じルートの再登録は既存登録を選択します。
- SettingsのDisplay Nameを編集しSaveまたはEnterで保存。Reloadは手動の全再走査です。Cancel scanでキャンセルできます。
- Deleteは登録とそのインデックスだけを削除します。実ファイルの編集・移動・削除APIは使用しません。
- フォルダ名・ファイル名を再帰的に索引化し、空フォルダも含めます。Python版同様、`.` で始まる項目を除外します。本文は検索しません。
- `alpha beta` はAND、`alpha OR gamma` はOR、`cat -draft` は除外、`"gamma delta"` は連続したフレーズの部分一致です。`OR` は大文字小文字を区別しません。除外は全ORグループに適用されます。
- Python版のPOSIX shlex風引用符・バックスラッシュ処理、不正な引用符の空白分割へのフォールバックを移植しています。
- ファイル検索のANDは1つのファイル名の中で成立する必要があります。別々のファイルの語を組み合わせません。
- 結果は親フォルダごとに集約し、深さ → フォルダ名 → 相対パスの順で表示します。最大100フォルダ。ルート自体も検索対象です。
- フォルダ名一致時のバッジは直下の全ファイル数、ファイル名のみ一致時は一致ファイル数です。除外のみの検索はフォルダ名を対象としバッジは0です。空検索は結果なしです。
- 展開時は、一致した直下の項目を表示します。フォルダ名一致の結果では直下の非一致ファイルも表示します。浅いフォルダプレビューでは全直下項目を表示します。
- Python版のUnicode casefoldとSQLite LIKE候補抽出のASCII大文字小文字処理も移植しています。既存の非ASCII大文字小文字の候補抽出制約を引き継ぎます。
- PDFはEdge内蔵PDF表示、画像はブラウザ対応形式を使用します。Office文書は非対応案内。その他は先頭16 KiBだけをUTF-8 → Shift-JIS（CP932互換）→ UTF-8置換の順で表示します。NULを含むバイナリは表示しません。HTMLも文字列として表示します。
- テーマ、検索対象、検索語、展開状態、選択パスを保存します。再起動時はファイルプレビューを自動で開かず、クリックして権限を確認します。

## 保存・権限・制約

- IndexedDB `file-search-html-v1` にルートハンドル、名前・相対パスの索引、設定を保存します。ファイル本文やプレビュー画像自体は保存しません。既存SQLite DBとは完全に独立しています。
- 同じEdgeプロファイル・同じHTML配置で利用してください。`file://` の保存領域・ハンドル復元・許可の寿命はブラウザの実装とポリシーに依存し、永続的な権限は保証できません。
- 読み取り権限を確認してから保存索引を即時検索します。権限がprompt / denied、ハンドルが使用不可、走査中の子階層アクセス拒否の場合は旧結果も隠します。索引自体は削除しません。SettingsのAllow access / Reselect / Reloadで明示的に復旧してください。バックグラウンド処理やプレビュー復元から権限を要求しません。
- Reselectは同じ実フォルダかを`isSameEntry`で確認してハンドルを再保存します。違う場所へ移したフォルダは別登録として追加してください。
- 走査が完了してから、ルート情報と索引を1つのIndexedDBトランザクションで置換します。キャンセル、読み取り拒否、消失、保存失敗では前回の索引を残します。初回走査の失敗時は「Not scanned」の登録が残ります。アクセス不能なサブフォルダは、部分索引への黙った置換を避けるため全走査失敗として扱います。
- 保存索引を表示した後、ルートごとにページセッション内で原則1回だけ非同期全走査します（索引未作成なら初回走査）。完全成功時だけ原子的に保存し、現在の検索語で結果を置換します。自動更新の進捗・更新件数は表示しません。展開・選択パス・入力を保持します。検索入力ごとの走査や定期監視はしません。以降の変更や失敗後の再試行にはReload、またはAllow access / Reselectを使います。同じルートの走査中のReloadは既存走査の完了を待ちます。
- ブラウザは絶対パスを公開しないため、表示はルート名と相対パスです。Explorer起動、ファイル移動、本文検索、Python SQLiteの取り込みは対象外です。
- 走査・検索は定期的にイベントループへ制御を戻します。索引はメモリ上に構築して保存するため、巨大なフォルダはメモリ・IndexedDB容量・保存時のstructured cloneの制約を受けます。保存中のキャンセル、全規模でのフリーズ回避は保証しません。
- InPrivate、保存容量不足、ブラウザデータ削除、組織ポリシーで保存やAPIが禁止された場合には利用できないことがあります。ブラウザデータを削除すると索引も消えるため再登録・再走査が必要です。
- PDFやHEIC/TIFFなどの画像表示可否はEdgeバージョン、コーデック、PDF表示ポリシーに依存します。PDFの描画成功はJavaScriptから自動判定していません。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html`, `styles.css` | 既存検索UIの情報構造、Settings、レスポンシブ表示 |
| `app.js` | 画面状態、ルート管理、検索・プレビュー、Object URL解放 |
| `filesystem.js` | read-only権限、非同期走査、相対パス解決、テキスト読込 |
| `storage.js` | IndexedDB、トランザクション単位の保存・削除 |
| `search.js` | 検索パーサー、候補抽出、親フォルダ集約、子項目一覧 |
| `tests/browser.html` | 直接起動用のロジック・実IndexedDBテストと実API検証 |

## 開発用テスト

以下のPython / Nodeは**開発テストだけ**で使います。アプリ起動には不要です。追加のPythonパッケージ・npm installは不要です。リポジトリ直下で実行します。

```sh
node html/tests/app-tests.cjs
node html/tests/run-core.cjs
python -m unittest discover -s html/tests -p 'test_*.py' -v
python -m unittest discover -s tests -v
```

## Windows Edge直接起動CI

`.github/workflows/edge-file-direct.yml` が `main3` 向けPRのHTML変更時に `windows-latest` で実行されます。`html/tests/edge-file-ci.cjs` がプリインストール済み `msedge.exe` を実際に起動します。Playwright CoreはCIの一時領域にだけインストールし、ブラウザのダウンロード・アプリへの依存追加は行いません。

- `index.html` と `tests/browser.html` を実際の `file:///...` URLで読み込み、タイトル、HTML・相対CSS/JSの読み込み、初期化完了、例外/console error/リソース失敗、`isSecureContext`、ネイティブ `showDirectoryPicker` の存在を確認します。
- Settingsと検索画面の初期表示・往復操作、アプリの検索語とテーマの保存を確認します。
- 実IndexedDBへ書き込み・読み戻し後、Edgeを正常終了。CDPで観測したブラウザ/renderer/utilityプロセスの終了をWindowsで確認し、同じ一時プロファイルで新しいEdgeを起動して保存値・設定とブラウザテストのマーカーを復元します。
- 既存 `browser-tests.js` のボタンを実際にクリックします。28共有ロジック項目のフォルダハンドル・権限・走査は模擬データです。同じページの保存/再読込/ロールバック/削除7項目は実IndexedDBを使います。レポートでも区別します。
- localhostやHTTPサーバー、通信の差し替え、APIモックの注入、権限の自動付与は使いません。Playwrightの既定起動引数を全て外し、Edgeにはプロファイル、制御用パイプ、初回案内の抑止、空白ページだけを指定します。セキュリティ機能を緩める引数は渡しません。
- 成否と詳細はActionsのサマリーおよび `windows-edge-file-direct-<attempt>` artifactに保存します。`report.json`、`driver.log`、ページログ、スクリーンショットとHTMLを含み、テスト失敗時もアップロードします。起動そのものに失敗した場合は画面を取得できないためログで確認します。

**CIのWindows Edge成功はユーザー実機の受入完了を意味しません。** フォルダ選択ダイアログ、実フォルダへの許可・再許可、実ハンドル保存/復元、実フォルダの走査、PDF/画像プレビュー、IME、大量ファイル、ユーザーのプロファイルと組織ポリシーは手動受入として残ります。APIの存在確認はダイアログや走査の成功判定に使用しません。

CI結果はPR #3・Issue #2に実行URL付きで記録します。Draftは維持します。

## キャッシュ即時検索・自動更新の追加検証
