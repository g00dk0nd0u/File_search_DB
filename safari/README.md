# Folder Search — Safari（本番UI）

`safari/` フォルダをそのまま保存し、MacのSafariで **`index.html` を直接開いて**ください。
Python、Node、localhost、Webサーバー、拡張、CDN、ビルド、外部ネットワークは実行時不要です。
隣接する `search.js`・`core.js`・`app.js`・`styles.css` も一緒に保持してください。

## 操作

1. **Settings → Add Directory** で検索対象フォルダを選択します。
2. 検索画面のルート選択プルダウンで登録ルートを切り替えます。
3. キーワード入力中に検索します。SearchボタンやEnterでも検索できます。
   日本語IMEの変換中は検索せず、確定後に検索します。
4. 結果は親フォルダ単位です。フォルダを展開し、直下ファイルを選択してプレビューします。
   フォルダ名が一致し、その子孫を含め検索語とフィルターの両方に一致するファイルがない結果は、初期状態で閉じます。開くと、検索語に一致しない名前のファイルも含め配下を表示します。
   子孫に検索語とフィルターの両方に一致するファイルがある結果は初期展開し、そのファイルと到達に必要なフォルダだけを表示します。結果フォルダ単位で判定します。
   同じ検索条件の再描画では、手動で開閉した状態をルートごとに保持します。
   検索語を変更すると一致種別に応じた初期状態へ戻ります。ファイル選択はルートごとに保持し、検索入力のフォーカスを移動しません。
   一致する肯定キーワードを淡いオレンジで強調します。除外語は強調せず、引用フレーズは全体を強調します。
5. 追加・削除を反映するには **Settings → 対象の登録 → 再選択** でフォルダを選び直します。
6. Settingsでは表示名の変更、登録削除ができます。実ファイルは変更・削除しません。
7. **Settings → Dark Mode** でLight / Darkを切り替えます。Space/Enterでも操作でき、押下状態と現在のテーマを表示します。
   検索画面にも即時反映し、索引作成やフォルダ再選択は不要です。専用localStorageキー `file-search-safari-theme` のみを保存し、
   既存IndexedDBのルート/索引・DBバージョンは変更しません。保存不可時もその画面で切替可能で、保存失敗を通知します。
   保存の寿命はSafariのプロファイル・ブラウザデータ削除・HTML配置等に依存し、file://での完全終了後復元は実機受入項目です。

検索はファイル名・フォルダ名のみ（本文・親パスの全文検索はしません）。
ANDは空白、ORは `OR`、除外は `-draft`、フレーズは `"alpha beta"`。
例: `報告 OR report -draft`。キーワードもフィルターも指定しない場合は結果を表示しません。
検索結果は全件を対象とし、深さ → フォルダ名 → 相対パスの順に最初の100フォルダを表示します。
「さらに100件表示」で次の結果を追加し、表示済み / 総件数を示します。最後まで表示するとボタンは消え、
検索条件またはルートを変更すると先頭100件に戻ります。
更新日6択・ファイル形式12択は、フォルダ名のみ一致した結果を開く場合にも適用します。
フィルター指定時は、対象ファイルが子孫を含め存在しないフォルダを表示しません。キーワードなしでもフィルター検索できます。
AND/OR/除外/フレーズは一致判定に適用します。フォルダ名のみ一致した結果では、検索語に一致しない名前
（除外語を含む名前も含む）も表示対象ですが、更新日・形式の条件は適用します。

初回の子項目生成は画面全体で400項目・各結果から8階層までとし、以降は「さらに表示」で続けます
（直下項目は200件ずつ、1操作での追加生成も400項目まで）。表示は再帰呼出しを避けたキューで処理し、
検索・ルート切替時に古い描画を中止します。親フォルダ索引をセッション単位で再利用し、検索・並べ替えの途中で
制御を戻します。巨大な索引はメモリやブラウザの保存容量に制約されます。

`search.js` の検索判定・結果集約・表示対象の処理はEdge版と共通です。
Python版の構文、Unicode照合、並び順、ファイル一致の親フォルダ集約に合わせています。
隠し名（`.`で始まるファイル・フォルダ）はPython/Edgeと同様に索引から除外します。
Python版自体は変更していません。

## Safariの制約と保存

- `webkitdirectory` / `webkitRelativePath` を使用します。`showDirectoryPicker()` や永続ディレクトリハンドルは使いません。
- ファイルアクセスは選択したページのセッション内だけです。**Safari完全終了・ページ再読込後は再選択が必要**です。
  BFCacheからの復帰でも以前のFileアクセスを無効化します。
- 保存済みの索引を読み込んでも、再選択前に古い検索結果やプレビューは表示しません。
- 絶対パス・永続識別子は取得できません。同名のフォルダを自動的に同一と判断しません。
  Add Directoryは常に別登録です。特定の登録に対する再選択は、利用者が明示的にその登録内容を置き換える操作です。
- 再選択開始時に対象の旧結果・プレビューを隠します。キャンセル、読取失敗、保存失敗では旧結果へ戻りません。
  新規追加の失敗時も直前の結果へフォールバックしません。別ルートを選択する操作は可能です。
- 索引の全件生成・読取確認後、登録情報と完成索引を**1つのIndexedDBレコード・単一トランザクション**で保存します。
  完了後にのみ検索へ公開します。部分的な索引は公開・保存しません。
  再選択・ルート切替・ページ離脱は処理世代を無効化し、進行中の書込を中断します。
- 本番DBは `file-search-safari-v1` の `roots` ストアです。
  UUID、表示名、選択フォルダ名、保存日時、ファイル名/相対パス/サイズ/更新時刻、フォルダ索引を保存します。
  File、本文、ディレクトリハンドルは保存しません。
  PoCの `file-search-safari-phase0-v1` は移行・削除せず保持します。
- 走査・読取・保存失敗では前回の保存レコードを破壊しません。プレビューの実読取失敗でもセッション索引と画面を隠します。
  選択後の権限失効をブラウザが即時通知する仕組みはないため、読取時に検出します。
- **無操作の自動再走査はありません。空フォルダの完全列挙はできません。** ファイル0件の選択は登録・索引置換に使いません。
  Safariが入力一覧から省略した項目はアプリ側では知ることができません。
- IndexedDBの寿命はSafariのプロファイル、プライベートブラウズ、HTMLの移動、ブラウザデータ削除等に依存します。
- PDFはSafari内蔵表示、画像は対応するラスター形式です。テキストは先頭16 KiB、UTF-8/Shift-JIS候補。
  UTF-8の切出し末尾が日本語文字の途中でも誤判定しません。HTMLは実行せず文字列として表示します。
  バイナリ・Office表示は保証しません。画像やPDFの対応形式・描画はSafariに依存します。

## コンパクトUI・プレビュー配置

基本14px / 行間1.5、カード8〜9px、ファイル行3px、カード間6px、ネスト10pxに縮小しました。
プレビューをDOM順でも先頭に置き、左2/3・結果右1/3のCSS Gridにしました。Tab順もDOMに従い、
プレビュー更新で結果の操作フォーカスを移動しません。800px以下はプレビュー→結果の1列で、stickyを解除します。
長い名前は折り返し、Gridの最小幅を0にして横溢れを防ぎます。Settings表だけは必要に応じて内部で横スクロールします。
空パネル最小高さは280→316px、PDFの高さと画像/テキスト上限は65vhから36px拡張し、画面高さでも制限します。

## Finder連携の調査結論

2026-10-26調査：追加インストールなし・file://直接起動・webkitdirectoryという条件で、対象の実ディレクトリを
Finderで直接開く正式なWeb APIは確認できず、実装していません。
[Entries API仕様](https://wicg.github.io/entries-api/#dom-file-webkitrelativepath)のパスは選択した階層内の相対パスです。
仮想ルートは実ファイルシステムのルートではなく、同名フォルダから絶対パスも復元できません。
Appleの[Finder表示API](https://developer.apple.com/documentation/appkit/nsworkspace/activatefileviewerselecting(_:))は
ネイティブAppKitのNSWorkspace APIで、SafariのページJavaScriptには公開されていません。
file://へのリンクだけでFinder起動を保証することもできません。
ダミーのFinderボタン、独自URLスキーム、AppleScript、拡張、ヘルパーは追加していません。
相対パスコピーは手動で場所を探す補助にはなりますが、絶対パスやFinder直接起動にはなりません。
今回は表示をコンパクトに保つため追加せず、別機能として検討可能です。
