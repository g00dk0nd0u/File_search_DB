# Folder Search — Safari（本番UI）

`safari/` フォルダをそのまま保存し、MacのSafariで **`index.html` を直接開いて**ください。
Python、Node、localhost、Webサーバー、拡張、CDN、ビルド、外部ネットワークは実行時不要です。
隣接する `search.js`・`core.js`・`app.js`・`styles.css` も一緒に保持してください。

## 操作

1. **Settings → Add Directory** で検索対象フォルダを選択します。
2. 検索画面のルート選択プルダウンで登録ルートを切り替えます。
3. キーワード入力中に検索します。SearchボタンやEnterでも検索できます。
   日本語IMEの変換中は検索せず、確定後に検索します。
4. 結果は親フォルダ単位です。フォルダを展開し、直下ファイルを選択してプレビューします。
   フォルダ名が一致した場合は直下の全ファイルを表示します。サブフォルダはさらに展開できます。
   結果と表示対象のサブフォルダは最初から展開します。同じ検索語の再描画では、手動で閉じた状態をルートごとに保持します。
   検索語を変更すると初期展開へ戻ります。ファイル選択はルートごとに保持し、検索入力のフォーカスを移動しません。
   一致する肯定キーワードを淡いオレンジで強調します。除外語は強調せず、引用フレーズは全体を強調します。
5. 追加・削除を反映するには **Settings → 対象の登録 → 再選択** でフォルダを選び直します。
6. Settingsでは表示名の変更、登録削除ができます。実ファイルは変更・削除しません。

検索はファイル名・フォルダ名のみ（本文・親パスの全文検索はしません）。
ANDは空白、ORは `OR`、除外は `-draft`、フレーズは `"alpha beta"`。
例: `報告 OR report -draft`。空の検索では結果を表示しません。
結果は最大100フォルダです。初回の子項目生成は画面全体で400項目・各結果から8階層までとし、
以降は既存の「さらに表示」で続けます（直下項目は200件ずつ、1操作での追加生成も400項目まで）。
表示は再帰呼出しを避けたキューで少しずつ処理し、検索・ルート切替時に古い描画を中止します。
大きな索引でフォルダごとに全件走査を繰り返さないよう、表示用の親フォルダ索引を使います。
検索判定や検索対象は変えません。
検索画面には件数・重複パス・常設の操作説明を表示しません。100件に達する場合は検索語で絞り込んでください。

`search.js` は `main3` のEdge版 `html/search.js`
（`b4b1cc53741a16938592f225ffb63cb28de1d566`）からの**同一コピー**です。
Python版の構文、Unicode照合、並び順、ファイル一致の親フォルダ集約に合わせています。
隠し名（`.`で始まるファイル・フォルダ）はPython/Edgeと同様に索引から除外します。
既存Python版・Edge版は変更していません。

## Safariの制約と保存

- `webkitdirectory` / `webkitRelativePath` を使用します。`showDirectoryPicker()` や永続ディレクトリハンドルは使いません。
- ファイルアクセスは選択したページのセッション内だけです。**Safari完全終了・ページ再読込後は再選択が必要**です。
  BFCacheからの復帰でも以前のFileアクセスを無効化します。
- 保存済みの索引を読み込んでも、再選択前に古い検索結果やプレビューは表示しません。
- 絶対パス・永続識別子は取得できません。同名のフォルダを自動的に同一と判断しません。
  Add Directoryは常に別登録です。特定の登録に対する再選択は、利用者が明示的にその登録内容を置き換える操作です。
- 再選択開始時に対象の旧結果・プレビューを隠します。キャンセル、読取失敗、保存失敗では旧結果へ戻りません。
  新規追加の失敗時も直前の結果へフォールバックしません。別ルートを選択する操作は可能です。
- 索引の全件生成・読取確認後、登録情報と完成索引を**1つのIndexedDBレコード・単一トランザクション**で保存します。
  完了後にのみ検索へ公開します。部分的な索引は公開・保存しません。
  再選択・ルート切替・ページ離脱は処理世代を無効化し、進行中の書込を中断します。
- 本番DBは `file-search-safari-v1` の `roots` ストアです。
  UUID、表示名、選択フォルダ名、保存日時、ファイル名/相対パス/サイズ/更新時刻、フォルダ索引を保存します。
  File、本文、ディレクトリハンドルは保存しません。
  PoCの `file-search-safari-phase0-v1` は移行・削除せず保持します。
- 走査・読取・保存失敗では前回の保存レコードを破壊しません。プレビューの実読取失敗でもセッション索引と画面を隠します。
  選択後の権限失効をブラウザが即時通知する仕組みはないため、読取時に検出します。
- **無操作の自動再走査はありません。空フォルダの完全列挙はできません。** ファイル0件の選択は登録・索引置換に使いません。
  Safariが入力一覧から省略した項目はアプリ側では知ることができません。
- IndexedDBの寿命はSafariのプロファイル、プライベートブラウズ、HTMLの移動、ブラウザデータ削除等に依存します。
- PDFはSafari内蔵表示、画像は対応するラスター形式です。テキストは先頭16 KiB、UTF-8/Shift-JIS候補。
  UTF-8の切出し末尾が日本語文字の途中でも誤判定しません。HTMLは実行せず文字列として表示します。
  バイナリ・Office表示は保証しません。画像やPDFの対応形式・描画はSafariに依存します。

## 本番UIのMac Safari受入手順（未検証）

本番UIはPhase 1〜3実装済みで、コードの自己精査・自動回帰を実施しています。Phase 4のMac Safari実機受入は別途必要です。

1. このブランチの `safari/` 全体をMacに配置し、Safariで `index.html` を直接開く。
   レイアウト、外部JS/CSS読込、Settingsへの移動を確認する（旧PoCと構成が異なるため再確認）。
2. 日本語・多階層・PDF・PNG・UTF-8/Shift-JISテキストを含むフォルダを登録。
   `alpha beta.txt`、`alpha draft beta.txt`、`gamma delta.txt` 等を用意し、
   `alpha beta`、`alpha OR gamma`、`alpha -draft`、`"gamma delta"` とPython/Edgeの結果を比べる。
3. 親フォルダ単位の集約・初期展開・手動折りたたみと再展開・ファイル選択を確認する。
   同じ検索語では閉じた状態が戻り、検索語変更後は開くこと、表示名の一致部分だけが淡いオレンジになることを確認する。
   PDF/画像/テキスト描画、IME入力中の挙動、深階層や大量ファイルでの「さらに表示」も確認する。
   テキスト、実PDFのエラー時挙動、HEIC等の任意形式は特に未検証。
4. 第2ルート（同名フォルダも可）を登録し、表示名変更・プルダウン切替・登録削除を確認。
   同名であっても勝手に統合されないことを確認する。
5. Mac側でファイルを追加・削除し、Settingsの対象登録の「再選択」で選び直す。新しい一覧と検索結果に置換されることを確認。
   選択キャンセル・選択拒否・アクセス失効・途中読取エラーでは旧結果とプレビューが消えることを確認。
   再選択成功で復帰し、失敗で前回保存データを破壊していないことも確認する。
6. キーワードを連続入力し、検索中のルート切替・再選択・プレビュー選択を繰り返し、古い非同期結果が出ないことを確認。
7. Safariを完全終了して再起動し、同じHTMLを開く。登録表示名は戻り、再選択前は検索不可・旧結果/プレビュー非表示。
   明示的に再選択した後だけ検索できることを確認する。
8. 空フォルダ、0ファイル、読取不可項目、ストレージ容量不足、大量ファイル、プライベートブラウズも別途確認。
   実機未検証です。空フォルダ完全列挙や自動再走査ができるとは判断しないでください。

確認結果にはSafariバージョン、対象件数、操作、期待値/実際の表示を記録してください。
